Ты работаешь в режиме автономного Инженера-Исполнителя. Твоя задача: реализовать фичу или исправление по запросу: $ARGUMENTS

Алгоритм действий:
1. Изучи затронутые файлы. Прочитай CLAUDE.md и каждый файл, типы и сигнатуры перед правкой.
2. Напиши чистый, строго типизированный код без `any`, `@ts-ignore` и временных заглушек. Соблюдай дизайн-систему, мобильную адаптивность и правила из CLAUDE.md.
3. Обязательно запусти в терминале `npm run verify`.
4. Если сборка или типы упали, самостоятельно исправь ошибки и повторяй шаг 3, пока билд не станет полностью чистым.
5. Если изменен UI (компонент, страница, модалка, стили), проверь его в настоящем headless-браузере:
   - добавь или обнови сценарий в `tests/smoke/ui-smoke.spec.ts`: открой измененный экран, кликни по новому элементу (например, кнопка, открывающая модалку) и проверь результат;
   - запусти `npm run test:ui` (в облачной сессии с `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium`); тест падает на белом экране, `pageerror` и `console.error`;
   - открой скриншоты из `/tmp/ui-check` инструментом Read и посмотри на десктоп и мобильный вид: отступы, переполнение текста, z-index, скролл модалок. Если что-то выглядит сломанным, исправь и повтори шаги 3 и 5.
6. Выдай краткий технический отчет: какие файлы изменены, результат `npm run verify` и `npm run test:ui`, какие скриншоты просмотрены и что не проверялось.
